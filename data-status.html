자동 갱신 정책과 반영 순서

단계시점·장소처리·검증 기준
1. 수집 시작GitHub Actions · 법원 매일 04:10 KST · 온비드 매일 06:20 KST법원은 17개 시·도 기본목록 전 페이지를 한 실행에서 수집하고, 온비드는 공식 API를 사용합니다. 예약 실행은 지연될 수 있습니다.
2. 조회·검증수집 실행 중법원은 시·도별 첫 페이지 totalCnt와 실제 누적 행수를 대조하고 17개 시·도 완주를 확인합니다. ipcheck=false·403·429 발생 시 우회하지 않고 중단하며 마지막 정상 스냅샷을 유지합니다.
3. 가공·저장전국 목록 검증 후고유 사건·물건으로 중복 제거한 압축 목록 JSON과 매니페스트를 생성합니다. 법원 상세 JSON 1.7만 개를 미리 만들지 않습니다.
4. 목록 반영전국 검증 성공 시전국 기본목록 PR을 생성·병합하고 Pages 배포를 실행합니다. 전수수집 실패 시 기존 정상 목록을 교체하지 않습니다.
5. 상세 조회사용자가 법원 물건을 선택할 때목록 기본정보는 즉시 표시하고, 상세가 필요하면 서울 리전 Vercel Function이 법원 사건·물건 상세를 1회 조회합니다. 성공 응답은 6시간 CDN 캐시하고 실패 시 기본정보와 법원 원문 링크를 유지합니다.
